# 완료 판정 절차

"완료"는 결정적 검증기가 판정한다. LLM(나 자신 포함)이 "잘 된 것 같다"고 판단하는 건 완료가 아니다.

## 절차

1. 아래를 실행한다.
   ```bash
   npm run typecheck
   ```
   이 저장소엔 테스트/lint 설정이 없다(`docs/harness.md` 참고) — 자동 검증 가능한 건 타입체크뿐이다.
   테스트나 lint가 나중에 추가되면 이 절차에도 반영한다.
2. **실패하면 완료 보고를 하지 않는다.** 실패 원인을 분석해서 구현을 고친다.
3. **타입 에러를 피하려고 타입을 `any`로 바꾸거나 검사를 우회하고 싶은 유혹이 들면, 멈춘다.**
   타입 정의 자체가 틀렸다고 판단되면 왜 그렇게 생각하는지 사람에게 설명하고 먼저 물어본다.
4. 통과하면, **명령 실행 결과 전체(요약 말고 실제 출력)**를 완료 보고에 그대로 포함한다.
   "타입체크 통과했습니다"라고 말로만 쓰지 않는다.

## 완료 보고 형식

```
✅ 완료: {무엇을 했는지 한 줄}

typecheck 결과:
{실제 npm run typecheck 출력}
```

## 이 스킬이 막으려는 것

- "대부분 통과했다"를 완료로 보고하는 것
- 증거 없이 "잘 됐다"고 말로만 보고하는 것
- 실패한 타입체크를 타입을 느슨하게 바꿔서(`any` 등) 우회하는 것
